# changelog

> 变更记录：东西改了不记，出问题时就只剩一句"之前还好好的"。

## 简介

这里记录值得留痕的变更——改了什么、什么时候改的、为什么要改。看的人通常只关心一件事：这次改动会不会影响到我。

## 目录结构

| 目录 / 文件 | 说明 |
| --- | --- |
| `current/` | 进行中的变更草稿 |
| `archive/` | 已发布的变更，按年归档 |
| `breaking.md` | 不兼容变更单独列出，附迁移说明 |
| `templates/entry-template.md` | 变更条目模板 |

## 条目格式

一条变更四段，按影响程度排序：

```markdown
## [版本号或日期]

- 新增：
- 变更：
- 修复：
- 移除：
```

每条改动后补一句影响说明，尤其是会影响别人的那几条。

## 写作原则

- 站在看的人角度写，写"会影响什么"，不写"我改了什么"
- 不兼容变更必须单独进 `breaking.md`，并给出迁移步骤，不能只说"有 breaking change"
- 一次变更一个条目，别攒着一起写，攒久了就写不准了
- 内部重构、不影响使用的改动可以不记，避免噪音
